# Java：函数式设计，简短实现

**两项首要目标：设计必须以函数式为核心；实现必须简短、简洁。正确性、外部契约、Java 版本和真实框架约束不可牺牲。**

## 设计：纯函数核心，副作用边界

- 把业务规则写成“输入 → 返回值”的纯函数：相同输入得到相同结果，不读写数据库、网络、共享状态或调用者对象。
- 用不可变数据表达输入、结果和状态；状态转换返回新值，不靠 setter 顺序隐式完成业务。`record` 内的可变组件仍需隔离，不能把浅不可变当深不可变。
- IO 留在薄编排层：**批量读取 → 纯计算 → 必要写入**。时间、随机数、ID 等非确定值在边界获取，再传给计算函数。
- 依赖用构造器注入，字段 `final`；纯计算不依赖 Spring 容器。框架要求可变的 JPA Entity 留在持久化边界，不强改成 `record` 或强制字段 `final`。
- 用函数和数据组合行为，不为单个实现创建接口、策略类、工厂、注册表或通用框架；不要为了“函数式”搬入新的函数式库。

## 实现：最少必要代码

- **同等正确、清晰时，选代码更少、状态更少、间接层更少的写法。** 能直接返回就不设中转变量，能用表达式就不维护结果变量，能复用现有 API 就不造工具类。
- 简短指删ea多余逻辑，不是压行、缩写命名或堆嵌套三元表达式。保留契约、错误语义和必要的业务分支。
- 默认一段逻辑就地表达；只有复用、独立业务含义或复杂度确实需要时才提取函数。禁止 `execute → process → doProcess` 等无价值转发。
- 小纯函数直接用普通方法；只有调用方确实需要传递或组合行为时才使用 `Predicate`、`Function`、`Supplier`。方法引用仅在比 lambda 更清楚时使用。
- 数据转换、筛选、聚合优先短小的 Stream 表达式；直接条件用 `if` / guard clause / 三元表达式，不用 `Optional.ofNullable(...)` 包装普通控制流。
- 不为少几行引入额外分配、装箱、重复遍历或复制；直接查找、集合 API、基本类型流或清晰循环更合适时就用它们。局部可变累加不等于共享状态，不为函数式外观强行改写。
- 删除死代码、重复判断、无用变量、样板、重复注释和过时兼容路径；不扩散到任务外的重构。

## 选择最小表达

| 需求 | 默认选择 | 不做 |
| --- | --- | --- |
| 数据载体 / 值对象 | `record`，版本与框架允许时 | 手写 getter/setter，滥用 builder |
| 简单条件 | 直接返回、guard clause、简单三元表达式 | `Optional` 链或策略框架代替 `if` |
| 有限常量 | `enum` | 字符串分派、多实现类 |
| 分支携带不同数据 | 确有建模价值时 `sealed` + `record` + 穷尽 `switch` | 为两个简单分支新增类型体系 |
| 集合纯变换 | `filter` / `map` / `flatMap` / 聚合 | 外部可变结果容器、为每步单建 helper |
| 可能缺失的返回值 | `Optional<T>`，使用 `map` / `flatMap` / `orElseThrow` | `Optional` 字段、参数、直接 `get()` |
| 不可变集合 | 按契约用 `List.copyOf` / `Map.copyOf` / `Stream.toList()` | 对已满足隔离要求的结果重复复制 |

只使用项目 Java 版本正式支持的语法；不为 `record`、模式匹配或 `switch` 开启 preview、升级版本或改变契约。`Stream.toList()` 不保证元素不可变，也不等同于可修改列表。

## 两个基准写法

纯转换直接返回，不创建可变中间集合或单次转发方法：

```java
List<String> activeNames(List<User> users) {
    return users.stream().filter(User::active).map(User::name).toList();
}
```

业务计算保持纯粹；已有值只需选择时，不包装成函数式管道：

```java
BigDecimal payable(BigDecimal total, BigDecimal discount) {
    return total.subtract(discount).max(BigDecimal.ZERO);
}

String displayName(String name) {
    return name == null ? "匿名" : name;
}
```

示例省略所在类、import 和契约文档；实际代码沿用项目约定，不以示例替代业务规则。

## 边界约束

- **Stream 只做内存计算**：不访问 Repository / Client，不修改外部状态，不用 `peek` 承载逻辑，不默认 `parallelStream`。构建 Map 时明确重复 key 的契约，不随意覆盖数据。
- **输入只在边界校验和规范化**：Bean Validation 必须在实际生效的入口执行；`@Valid` 本身不保证对象非空。按语义使用 `@NotNull` / `@NotBlank` 等约束；可选条件统一 trim、默认化。内部不重复防御性判空，不伪造默认成功结果。
- **Controller 做协议适配，Service 做用例编排和事务，Repository / Client 做 IO**；沿用现有分层，不为形式增加层数。纯计算可先放在当前类的命名方法中，不强制新建领域服务。
- **数据库和远程访问优先批量**：消除逐条查询，内存关联先建索引；超限分片，确认 ORM / 驱动实际批处理。分页用稳定排序；并发不变量由约束、版本或条件更新保障。
- **事务只覆盖一致性所需操作**；不能为了拆出纯函数破坏事务一致性。注意 Spring 自调用、异步线程不继承事务；远程调用设置超时，不擅自增加重试。
- **错误不吞、不伪装为空值**：按既有业务异常和错误码传播；包装时保留 cause，只在处理边界记录一次，日志避免敏感字段和完整请求响应。
- **金额与时间语义明确**：金额用 `BigDecimal` 并指定所需精度与舍入；时刻优先 `Instant`，日期用 `LocalDate`，不依赖默认时区。
- **命名与文档服务于契约**：使用简单类名与 import；类型明显时用 `var`。入参、出参和实体字段保留准确的业务注释，`record` 用 `@param`；其他注释只补充约束和原因，不复述代码。

## 执行与验收

1. 读取调用方、契约、项目版本和已有实现；先确定输入、返回值、不变量与副作用。
2. 先写最短的纯计算，再接必要 IO；优先减少状态和分支，其次才考虑抽象。
3. 删除可省略的变量、方法、类型、复制与重复校验；检查纯函数没有隐藏 IO、时钟读取或输入修改。
4. 运行受影响的编译、行为测试及实际路径；测试结果和边界，不断言源码写法。纯函数使用真实数据，只有外部边界需要替身；持久化改动观察真实 SQL / 批处理。

**最终判断：业务语义是否完整？核心是否纯粹？还能否删掉一层、一段状态或一行无价值代码？能删就删，不能以简短为由省掉正确性。**
